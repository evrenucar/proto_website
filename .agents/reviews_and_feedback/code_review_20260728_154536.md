# Code review: `fix-markdown-sidecar-405-error`

Date: 2026-07-28
Scope: full branch diff against `main`, plus the uncommitted working-tree change.
Outcome: 8 findings raised, 8 fixed, 2 further issues found during verification and left open.

---

## Main recommendations

1. **Never let a preview embed reach a write endpoint.** The worst bug here was not the camera logic, it was that a read-only landing preview held a live `/api/save-board` endpoint and a running autosave loop. Treat "preview" as a hard capability boundary, not a UI mode.
2. **Anything the generator emits must change in the generator.** Two of the eight findings were hand-edits to generated HTML that the next `npm run build` would have silently reverted.
3. **`npm run build` is not safe to run concurrently.** It deletes `content/` and restores from a single shared `.build-preserve` directory. Two overlapping runs destroy board content. This is currently reachable through the normal test command. See open issue 1.

## 1. Preview mode wrote back to the repository canvas

`applyWheelZoom` called `markBoardDirty()` with no preview guard. `markBoardDirty` set
`hasPendingRepositorySave`, `applyBoardSettings` started the autosave loop for previews too, and
`saveBoard` had no preview guard while `boardConfig.saveEndpoint` defaulted to `/api/save-board`.

Zooming the read-only preview on `cosmoboard-landing.html` therefore POSTed the whole board about
20 seconds later and rewrote `content/boards/onboarding/current.canvas` with the visitor's camera.

The uncommitted working-tree change at review time was exactly this: the key order matched
`serializeState()` output (`defaultViewport` relocated after `viewport`) and `viewport.z` had
dropped to `0.2116`.

**Reproduced live** before fixing. With the pre-fix runtime, ten synthetic wheel events on the
landing preview plus a 28 second wait changed the canvas hash from `6558e5181cbb` to `99d23076a502`.
With the fix, the same sequence leaves the file byte-identical and issues zero `/api/` requests.

Fix, in `JavaScript/braindump.js`:

- `markBoardDirty` sets `hasPendingRepositorySave` only when not in preview. Local persistence still
  runs, so the visitor's camera survives a reload.
- `startAutosaveLoop` returns early in preview.
- `saveBoard` returns `{ ok: false, skipped: true }` in preview as a last line of defence.

The stomped canvas was restored.

## 2. Cache-bust version missing from the generator

`scripts/build-site.mjs` still emitted `braindump.js?v=58` in both render paths while the branch had
hand-bumped the HTML to `?v=59`. The next build would have reverted `braindump.html`,
`cosmoboard.html`, `content/boards/eurocrate-storage.html` and `index.html` to `v=58`, serving stale
cached JS to returning visitors.

Fixed in the generator. The test now asserts the invariant (every generated page agrees on the
version) rather than a literal number, which had already gone stale twice.

## 3. `onboarding.html` orphaned from the build pipeline

`src/site-data.mjs` did not list an onboarding page, so the file was hand-written and never
regenerated, was missing from `sitemap.xml`, and its hand-written `data-board-index` listed four
boards while every generated page listed three.

Added `onboardingPage` to `src/site-data.mjs` and to `boardPages`. The page is now generated, in the
sitemap, and every board index agrees.

Note the generated page uses the site-wide `seoKeywords` rather than the hand-written
onboarding-specific keywords. The generator has no per-page keywords support, so this matches every
other page on the site.

## 4. `direction.md` emptied

The branch reduced `content/boards/cosmoboard/direction.md` from 25 lines to a single blank line
while four places still referenced it, including the new onboarding board's own "open this for a
longer example" markdown node, whose `_rawMarkdown` was also `""`.

This looks like the known `[BUG]` in the scratch pad (select-all and delete inside an empty markdown
window) landing on real content.

Restored from `main` and the `ob-direction-md` node refilled.

## 5. `defaultViewport` honoured only in preview

`applyPreviewCameraOverride` returned early outside preview, so the full board ignored
`defaultViewport` entirely.

Renamed to `applyCameraOverride(data, options)`. Preview behaviour is unchanged. In full board mode
`defaultViewport` now applies only on a first load straight from the source file, so it never
overrides a camera the author saved locally, nor an explicit import or diff apply.

Verified: a fresh `onboarding.html` load with cleared storage renders
`translate(40px, 30px) scale(0.55)`, matching the canvas `defaultViewport`.

While wiring this up, found that applying a `.canvas.diff` rebuilt state without `defaultViewport`,
silently dropping it on the next save. Now carried through.

## 6 to 8. Cleanups

- The comment claiming previews never write to their own storage key was false, and
  `getCanvasDraftStateForPreview` required a key ending in `:preview` while the landing page uses
  `board:onboarding:landing-preview`, so that whole draft-mirroring path had always been dead.
  Both fixed.
- The identity and version check was duplicated three times. Extracted to `checkStoredStateMeta`.
- `src/registry.json` described `cosmoboard` as the onboarding board and tagged it `onboarding`,
  colliding with the real onboarding entry. Reworded and retagged.
- `cosmoboard-landing.html` is hand-maintained but embeds a value the generator computes as a
  content hash. Synced, with a comment explaining it must be re-copied when the canvas changes.

## 9. Board-preview nodes pointed at export-bundle paths

Found via a console 404 during browser verification:
`GET /boards/cosmo-braindump_current.canvas` returned 404 on every page hosting the node.

Three nodes across two canvases carried export-bundle paths (`/boards/...`, `/markdown/...`) instead
of real content paths. The onboarding board inherited the broken value on this branch, so its
"linked board preview" demo node was dead on arrival.

`exportProjectBundle` operates on `cloneState(serializeState())` today, so the exporter is not
currently corrupting live state. This is frozen historical damage, not an active bug.

Repaired both `board-preview` nodes to `/content/boards/braindump/current.canvas` and
`/braindump.html`, matching the root-absolute convention used by sibling nodes in the same files.

## Open issues

### 1. `build()` is not concurrency safe and destroys `content/` (High)

`build()` in `scripts/build-site.mjs` does:

1. `preserveBoardContent()`: `rm -rf .build-preserve`, then copy `content/boards` into it
2. `rm -rf content/`
3. `restoreBoardContent()`: copy `.build-preserve` back

Two overlapping runs interleave on the single shared `.build-preserve` directory. Run B's step 1
wipes the preserve directory while run A is between its own steps 2 and 3, and run A restores
nothing.

This is reachable through the documented test command. `node --test tests/build/*.test.mjs` runs the
files in parallel and several call `build()`. During this review it deleted 54 tracked files under
`content/`, including every board except braindump. Recovered with `git checkout`, but only because
they were committed. Uncommitted board edits would have been unrecoverable.

Workaround for now: run build tests one file at a time. A real fix needs either a lock, a
per-run preserve directory, or dropping the `rm -rf content/` step in favour of targeted cleanup.

### 2. Build output is not reproducible across timezones (Low)

Rendered timestamps shift with the local timezone and DST, and `generatedAt` / `lastmod` use the
build date. Rebuilding today churned `projects.html`, `open-quests.html`, five project detail pages
and `content/entities/index.json` with pure noise (every "Last updated" moved by two hours). Those
files were reverted rather than committed. Rendering in a fixed timezone would make the build
deterministic.
